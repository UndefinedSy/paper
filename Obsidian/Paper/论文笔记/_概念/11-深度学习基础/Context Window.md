# Context Window

## 定义

大语言模型单次推理可处理的最大 token 长度上限，是一种有限、昂贵、延迟敏感的计算资源。

## 核心要点

1. 虽然近年来上下文窗口在持续扩展（如 Gemini 1.5 支持百万级 token），但对生产服务而言仍是**有限、成本高、延迟敏感**的资源——简单地把越来越长的历史塞进每次提示并不实用。
2. 上下文窗口是**瞬时、有界**的，而持久状态需要跨会话、跨时间维持——二者性质根本不同，这正是 [[Memory Base]] 范式存在的核心动机：用专门的记忆管理层弥合上下文窗口的瞬时性与长期交互所需的持久状态之间的鸿沟。
3. 即便未来模型上下文窗口足够大，naive 地注入全部历史仍会带来显著更高的 token 成本，以及长输入下 LLM 易受无关上下文干扰（over-squashing）的问题。

## 代表工作

- [[VikingMem]]: 论文开篇即以上下文窗口的有限性作为 Memory Base 范式存在必要性的核心论证起点。
