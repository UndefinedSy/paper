# Database Branching

## 定义

把数据库的**历史**在某个 [[LSN]] 处分叉成父子两条独立演进的时间线，从而获得"数据库版的 `git checkout -b`"。核心特征是创建开销为 **$O(1)$ 元数据操作**，不做任何物理数据拷贝。

## 核心要点

1. **共享与分叉**：父子分支共享 branch LSN 之前的历史（**同一份物理存储**），之后各自独立追加 [[WAL]]。实现上子分支只保存"父 timeline ID + branch LSN"的引用。
2. **branch LSN 的约束**：必须保证分支创建那一刻，父分支上该 LSN 处的**每一个页都可被重建**；实现简化为限制在父分支的 [[PITR]] 窗口内。
3. **事务语义**：未在 branch LSN 提交的事务，等同于崩溃恢复中的在途事务——被**中止**，其待定修改在子分支不可见。
4. **读的递归成本**：子分支的读若无法由自身层文件满足，会递归查父 timeline 的层。**深分支层级损害读性能，因为一次读跨更多 timeline**；因此 agent 定稿后应 detach 分支并提升为 root。
5. **detach / re-parent**：摘离父分支是瞬时元数据操作，PS 异步拷贝祖先数据到被摘离的 timeline；摘离后可重新挂到某个祖先之下。
6. **不支持合并**：分歧的物理数据如何调和没有良定义，通常需要应用层解决冲突。
7. **驱动场景**：agentic 工作流中代码与数据库状态**一起迭代分支**，每次 prompt 都可能产生新分支，生产观测存在超过 500 层深的分支树。

## 代表工作

- [[Lakebase]]: 以 [[Timeline]] 为承载实现 $O(1)$ 分支；与 [[PITR]] 共用同一套历史保留机制；正文定义为 agent 场景的一等原语。
- [[Neon]]: 同一分支机制的源头实现。
