# Hash Index

## 定义

基于哈希函数将 key 映射到存储位置（如磁盘 offset 或 bucket）的索引结构，提供 $O(1)$ 期望时间复杂度的点查找，但不维护 key 的顺序，因此不支持范围查询。

## 核心要点

1. 相比 [[LSM-tree]]（写放大 10–30×）与 [[B+ Tree]]（$O(\log n)$ 点查），哈希索引在纯点查场景下兼具最优查找复杂度与最低写放大（1×）。
2. 核心代价是失去 key 排序：无法支持 range scan、前缀查询等依赖顺序的访问模式。
3. 哈希碰撞需要解决方案（如 [[分离链表|separate chaining]]、开放寻址），并常以压缩 key 表示（如用 [[MD5]] 哈希代替完整字符串）换取空间效率，此时需评估碰撞概率是否可接受。
4. 对分布式 KV 系统而言，由于跨 shard 场景下即便 LSM-tree 系统也无法提供全局排序，哈希索引牺牲的"排序"价值在分布式部署中进一步被削弱，使哈希索引成为更具性价比的选择。

## 代表工作

- [[SOS]]：全量驻留内存的哈希索引，每条目仅 30 字节（96-bit MD5 key + 48-bit 时间戳 + 16-bit TTL + 16-bit service ID），配合[[分离链表]]解决碰撞，是实现"至多一次磁盘 I/O"设计不变式的核心组件之一。
- [[Bitcask]]、[[SILT]]：同样采用哈希索引实现 $O(1)$ 查找，但依赖周期性 merge 回收 append-only log 空间。
- [[FASTER]]：hybrid log 架构下的哈希索引，面向单机高吞吐场景。
