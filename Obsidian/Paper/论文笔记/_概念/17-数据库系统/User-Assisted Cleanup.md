# User-Assisted Cleanup

## 定义

当版本清理器持续无法获取表级锁时，将清理工作委托给恰好持有该冲突锁的用户事务：清理器维护「锁资源 ID → 被跳过页列表」的哈希表，用户事务每条语句结束时检查自己持有的锁资源 ID 是否在表中，若在则清理其中一部分页。

## 核心要点

1. 目前仅在用户事务持有表级排他锁（X 锁）时生效，持共享锁的事务无法触发（论文列为已知局限与未来工作）。
2. 每次事务内清理的页数量设有上限，避免明显拖慢前台语句执行。
3. 哈希表本身容量有限；超限的页转入 [[Side List]] 留待 sweep 末尾重试。
4. 事务内清理操作幂等安全：中止不会引入正确性问题，失败会通过 Side List 被重试。
5. 与「直接覆盖中止版本」优化（Figure 3）互补：新事务更新含中止版本的行时可直接覆盖并链接到最新提交版本，进一步降低清理压力。
