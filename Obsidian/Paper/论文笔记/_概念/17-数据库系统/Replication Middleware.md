# Replication Middleware

## 定义
复制中间件是位于**计算节点与共享存储层之间**的一层组件，负责把主区域的 [[WAL]] 传输到其他区域。它把「跨区域复制」从请求服务的数据节点上剥离，从而让复制与本地分区管理彼此解耦。

## 核心要点
1. **解耦手法**：物理分区信息**只在所属区域内可见**，[[Regional Manager]] 管理的分区元数据不跨区域复制。于是主区域与副本区域的分区对应关系是 **N-to-M** 而非严格一对一，各区域可独立 split/merge。
2. **Replicator Manager** 独立记录每个分区的复制进度（Plog ID + 已完成偏移），并保证**任何新分区谱系开始复制前，其所有前驱分区均已复制完成**。
3. **ACK 优化**：不在数据节点应答客户端后确认，而是**在副本区域 WAL 落盘后立即 ACK**；并把同一主节点内不同分区的确认**包聚合**为一条消息，携带 Plog ID 与最大已复制偏移。
4. **去重**：接收端跟踪每条 WAL stream 的最高已应用偏移，网络重试或 failover 导致的回退重传会被跳过。
5. **重放正确性**：靠 [[Epoch]] 控制可见性（epoch 内全部操作重放完才可见）+ 同 epoch 内幂等，因此可在任意 epoch 内任意点恢复重放。
6. **开销特性**：异步模式下复制器只读 WAL，不阻塞数据路径，吞吐开销 < 3%、延迟可忽略；同步模式最多降低 42% 吞吐。

## 代表工作
- [[K2Plus]]：在 [[DFV]] 之上实现该中间件，是论文的核心贡献。
- [[FoundationDB]]：把 TLog 从事务层解耦（思路相近但仍有 commit proxy 强制全局序）。
